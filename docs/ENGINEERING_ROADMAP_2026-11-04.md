# Evaluación y plan de ingeniería — java-paradigms-lab

**Fecha de revisión:** 2026-11-04. **Estado:** propuesta técnica basada en inventario y archivos consultados; no acredita pruebas ejecutadas ni producto comercial.

## Evidencia y contexto

Laboratorio académico Java; README declara paradigmas POO/funcionales, mientras main.java importa clases cl.unab.ptec102.ejemplopokemon.core.* cuya implementación no aparece en raíz.

## Cambios priorizados

1. Verificar procedencia de dependencias Pokemon/Gimnasio antes de afirmar ejecución independiente.
2. Agregar ejemplos autocontenidos de POO, streams, lambdas y pruebas por módulo sin depender de material de terceros.
3. Establecer JDK objetivo, estructura Maven/Gradle y guías de ejecución por ejemplo; no incorporar código Pokemon de terceros sin licencia.

## Criterio de aceptación

Al menos un ejemplo autocontenido compilado y probado; README separa lo demostrable de lo incompleto.

## Protocolo Git y preservación

- Crear ramas temáticas y pull requests con cambios pequeños y pruebas; no publicar ejercicios o trabajos ajenos sin permisos.
- Conservar autoría, fechas, informes originales y licencia aplicable. Un derivado comercial requiere evaluación independiente de titularidad.
- No atribuir a MasterTech SpA automáticamente trabajos académicos previos.
- Documentar comandos ejecutados y resultados reales; no inventar métricas ni despliegues.
